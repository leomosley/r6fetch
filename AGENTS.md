# AGENTS.md

Operating manual for AI agents working in the **r6fetch** repo. Read this before
touching anything. These are rules, not suggestions.

r6fetch serves Rainbow Six Siege stats over `curl`. The product is a terminal
experience first, a website second. Every change is judged against that.

---

## 1. Guardrails — do NOT do these

- **Do NOT run builds.** No `bun run build`, `astro build`, `wrangler deploy`,
  `turbo run build`. Typechecking only.
- **Do NOT start servers or long-running processes.** No `bun run dev`,
  `wrangler dev`, `astro dev`, `turbo run dev`.
- **Do NOT deploy or apply infra.** Never run `wrangler deploy`, `tofu apply`,
  or `tofu plan` against real credentials. Deployment is CI/human territory.
- **Do NOT edit generated files.** `packages/renderer/src/rank-art-data.ts` is
  generated by `scripts/gen-rank-art.ts` and is prettier-ignored. Change the
  generator, never the output.
- **Do NOT touch binary assets** under `packages/renderer/src/ranks/*.webp`
  unless explicitly asked.
- **Do NOT commit secrets.** `.dev.vars`, `*.tfvars`, `.env*` are gitignored for
  a reason. Bindings and API keys come from Cloudflare/CI, never source.
- **Do NOT add dependencies casually.** See §4. Justify every new one.
- **Do NOT reformat unrelated code.** Keep diffs tight and on-topic.
- **Do NOT commit or push without human review.** Agents are not trusted to make judgment calls
  about correctness, style, or security. Every change must be reviewed by a
  human before merging.
- **Do NOT stage any files** when working with a human reviewer. Let them see the full diff and context.

### Verification you ARE allowed to run

- `bun run typecheck` — the canonical check (this is what CI runs).
- `bun install` — when dependencies genuinely change.
- Package-scoped typecheck, e.g. `bun run typecheck --filter=@r6fetch/api`.

If a typecheck fails after your change: **stop, do not revert, show the error,
and ask** whether it's a real logic error or a broken/missing-types environment.

## 2. Project shape

Bun + Turborepo monorepo. Package manager is **bun** (`bun@1.2.0`); never
introduce npm/pnpm/yarn lockfiles.

| Path                 | What it is                                                 |
| -------------------- | ---------------------------------------------------------- |
| `apps/api`           | Hono API on Cloudflare Workers. The curl endpoint.         |
| `apps/web`           | Astro marketing/docs site.                                 |
| `packages/r6-client` | Typed client for `r6.stats.cc`. Fetch + parse + normalise. |
| `packages/renderer`  | Pure ANSI terminal-art renderer. No I/O.                   |
| `infra`              | OpenTofu (`tofu`) for Cloudflare DNS/Workers/rate-limit.   |
| `scripts`            | One-off bun scripts (rank-art gen, bruno runner).          |
| `bruno`              | Bruno API collections for manual endpoint testing.         |

**Dependency direction (never violate):**
`renderer` → `r6-client`, `api` → both, `web` → `renderer`. Packages must stay
free of Cloudflare/Hono/Astro types. `renderer` performs no network or disk I/O
— it takes a `PlayerProfile` and returns a string.

## 3. TypeScript standards — strict, explicit, no escapes

The root tsconfig is strict with `noUnusedLocals` and `noUnusedParameters`.
Respect it and go further:

- **No `any`. Ever.** Untrusted input is typed `unknown` and narrowed. `as`
  assertions are a smell — use type guards (`isRecord`, `isValidPlatform`)
  instead. The only acceptable cast is narrowing `unknown` at a well-guarded
  boundary, as in `parseConfigResponse`.
- **Type the public surface explicitly.** Exported functions get explicit
  return types. Internal helpers may infer.
- **Prefer `type` unions and `interface` for object shapes**, matching existing
  files (`Platform`, `PlayerProfile`, `Bindings`).
- **Path aliases:** in `apps/api` import internal modules via `~/*`
  (e.g. `~/routes/stats`), cross-package via `@r6fetch/*`. Never use deep
  relative `../../` across package boundaries.
- **ESM only.** Every package is `"type": "module"`. No `require`.
- **No `ts-ignore` or `eslint-disable`.** If you need to disable a rule, fix the
  underlying problem instead.
- **No `@ts-expect-error`.** If a type error is expected, it's a bug. Fix it.
- **No single line if statements** — always use braces, even for one-liners. This is a safety measure to prevent accidental mis-scoping of code blocks.
- **Prefer Boolean over !!** for truthiness checks.\*\* Use `Boolean(value)` or explicit comparisons (`value !== null`) instead of double negation, which can be less readable and may lead to confusion.
- **Don't comment on code unless it is absolutely necessary** — strive for self-documenting code. Use descriptive variable and function names, and write clear, concise code that doesn't require additional explanation.
- If a comment is required and it is over 3 lines consider that the code is too complex and should be refactored into smaller, more manageable pieces.

## 4. Minimal dependencies

The stack is deliberately small: Hono, Astro, sharp (build-time only). Keep it
that way.

- **Default answer to a new dependency is no.** Reach for the platform first:
  Web `fetch`, `AbortSignal.timeout`, `URL`, `Set`, `Map`, Workers KV.
- If you believe a dependency is warranted, **stop and justify it** (what it
  replaces, why hand-rolling is worse, bundle/runtime cost on Workers) before
  adding it.
- Nothing Node-specific in Workers code — it runs on the edge runtime.
- No runtime dependency in `renderer` beyond `r6-client`. It stays pure.

---

## 5. Taste — readable over clever

The existing code is the style guide. Match it.

- **Small pure functions over classes.** The codebase uses exactly two kinds of
  class: typed **error** classes (`PlayerNotFoundError`, `ApiError`) and none
  else. Stateful things (the client, config cache) are closures returned by
  factory functions (`createClient`), not classes. Follow this. Don't introduce
  class hierarchies, decorators, or DI containers.
- **Compose named helpers.** Prefer `getTopOperator(...)`,
  `getCurrentSeasonRankedStats(...)` — one job each, descriptive name — over a
  single sprawling function or a dense one-liner chain. If a line needs a beat
  to parse, name the intermediate.
- **No cleverness for its own sake.** Idiomatic conditional spreads
  (`...(cond && { key })`) are fine because they're established here. Obscure
  bit-twiddling, nested ternaries, or golf are not.
- **Guard clauses and early returns** over deep nesting.
- **Immutability by default:** `const`, don't mutate inputs. Local sort-then-
  read (as in `getTopOperator`) is fine on freshly-built arrays.

## 6. Robustness — trust nothing from the network

`r6-client/src/normalise.ts` is the reference for handling external data. Match
its discipline:

- **Parse, don't assume.** Every external JSON response passes through a
  `parse*` function that validates required fields and rejects malformed core
  data (`parseProfileResponse`, `parseConfigResponse`). Optional fields degrade
  to sane defaults (`?? 0`, `?? null`), they don't throw.
- **Fail into typed errors.** Network/decode failures become `ApiError`;
  missing players become `PlayerNotFoundError`. Callers branch on
  `instanceof`. Preserve this contract — routes in `apps/api` depend on it.
- **Always bound network calls** with `AbortSignal.timeout(REQUEST_TIMEOUT_MS)`.
- **Never leak internals to users.** API error responses are calm, plain-text,
  and actionable (see `stats.ts`). No stack traces, no JSON error blobs.

---

## 7. The terminal output is the product

- Output is plain text with 24-bit ANSI, assembled by `renderer`. Use the
  helpers in `ansi.ts` (`fg`, `bold`, `padRight`, `visualWidth`) — never count
  raw string length for layout, because ANSI codes are invisible width.
- Keep curl/welcome/error copy in the established voice: two-space indent,
  em-dash separators, concise, friendly. Mirror `buildWelcome` and the setup
  scripts.
- The setup scripts (`setup.ts`) are shipped shell/PowerShell. Treat them as
  code: POSIX `sh` (not bash-isms), quote variables, `set -e`, idempotent
  edits (the `# BEGIN/END r6fetch` block pattern). Test logic mentally for both
  piped-stdin and TTY cases.

---

## 8. Formatting & commits

- **Prettier is authority.** `semi: true`, double quotes, 2-space, `printWidth:
100`, `trailingComma: es5`. Don't fight it or hand-format.
- Astro files use `prettier-plugin-astro`.
- Don't reformat files you didn't change.
- Keep commits focused and conventional; don't bundle unrelated changes. Only
  commit when asked.

---

## 9. Before you finish

1. `bun run typecheck` is green (or you've flagged an environment issue).
2. No new `any`, no stray `console.log`, no unused imports/vars.
3. No new dependency slipped in unjustified.
4. Generated files (`rank-art-data.ts`) untouched unless via the generator.
5. Diff is minimal and on-topic.
